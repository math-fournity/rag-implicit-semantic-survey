### 一、模型论语义学：意义的数学基础

#### 1.1 Montague语法的革命

1970年代，逻辑学家Richard Montague提出了一个大胆的主张：自然语言可以像数理逻辑一样进行严格的形式化处理。这一主张在当时极具争议——自然语言的复杂性、歧义性和语境依赖性似乎与数学的精确性格格不入。然而，Montague的工作最终证明了这种形式化的可行性，开创了形式语义学的现代范式。

Montague的核心洞见是：**自然语言的意义可以通过模型论（Model Theory）来精确定义**。在这个框架中：

- **语言表达式**被映射到**数学对象**
- **句子的意义**是其**真值条件（Truth Conditions）**
- **组合规则**决定了如何从部分意义构建整体意义

以简单句"John runs"为例，其形式语义分析如下：

1. "John"是一个专名（Proper Name），其意义是模型中的一个实体 $j$
2. "runs"是一个不及物动词，其意义是一个**谓词**——模型中具有"跑"属性的实体集合 $\{x : runs(x)\}$
3. 句子"John runs"的意义是判断 $j$ 是否属于这个集合：$runs(j)$

这种分析看似简单，却蕴含了深刻的原则：句子的意义不是模糊的"概念"，而是可以精确计算的真值条件。知道一个句子的意义，就是知道在什么条件下这个句子为真。

#### 1.2 可能世界语义学

Montague语法的强大之处在于它能够处理更复杂的语言现象。对于涉及必然性（necessity）、可能性（possibility）和信念（belief）的句子，Montague引入了**可能世界语义学（Possible World Semantics）**。

考虑句子"John必然是人类"（John is necessarily human）。这个句子的真值不能仅根据当前世界判断，而需要考虑所有可能的世界：

$$\Box Human(j) \Leftrightarrow \forall w \in W : Human_w(j)$$

其中 $W$ 是所有可能世界的集合，$\Box$ 是必然性算子。句子为真，当且仅当在所有可能世界中John都是人类。

这种分析框架对于RAG系统有重要启示：

**模态推理的形式化**：用户查询常涉及假设性问题（"如果X发生，会怎样？"）、可能性判断（"这可能是真的吗？"）、必然性断言（"这必须满足..."）。可能世界语义学提供了处理这类查询的形式化框架。

**信念与知识的建模**：RAG系统需要区分"系统知道什么"和"文档声称什么"。认知逻辑（Epistemic Logic）——可能世界语义学的扩展——为此提供了精确的工具。

#### 1.3 模型论语义学的形式化定义

让我们更严格地定义模型论语义学的核心概念：

**定义1（模型）**：一个模型 $\mathcal{M}$ 是一个二元组 $\langle D, I \rangle$，其中：
- $D$ 是**论域（Domain）**，即模型中所有实体的集合
- $I$ 是**解释函数（Interpretation Function）**，将语言表达式映射到语义值

**定义2（类型系统）**：Montague语法使用类型论组织语义类型：
- $e$：实体类型（Entities）
- $t$：真值类型（Truth values），取值为 $\{0, 1\}$
- 如果 $\alpha$ 和 $\beta$ 是类型，则 $\langle \alpha, \beta \rangle$ 是**函数类型**

常见语言表达式的类型：
- 专名（John, Mary）：类型 $e$
- 不及物动词（run, sleep）：类型 $\langle e, t \rangle$（从实体到真值的函数）
- 及物动词（love, see）：类型 $\langle e, \langle e, t \rangle \rangle$
- 句子：类型 $t$

**定义3（语义组合）**：如果表达式 $\alpha$ 的类型是 $\langle \sigma, \tau \rangle$，表达式 $\beta$ 的类型是 $\sigma$，则 $\alpha(\beta)$ 的类型是 $\tau$。

这就是著名的**函数应用规则（Function Application）**，是组合性原则的核心体现。

#### 1.4 与分布式语义学的对照

形式语义学与分布式语义学（Distributional Semantics）代表了两种截然不同的意义观：

| 维度 | 形式语义学 | 分布式语义学 |
|-----|-----------|-------------|
| **意义本体** | 外延对象、真值条件 | 向量空间中的点 |
| **核心假设** | 意义是指称关系 | 意义来自分布模式 |
| **组合方式** | 函数应用、类型驱动 | 向量运算（加法、乘法） |
| **主要优势** | 精确、可解释 | 可学习、鲁棒 |
| **主要局限** | 覆盖有限、脆弱 | 缺乏解释性、推理弱 |

值得注意的是，这两种范式并非完全对立。近年来，**形式-分布整合（Formal-Distributional Integration）**成为活跃的研究方向：

- **类型化张量模型（Type-Driven Tensor Calculus）**：将形式语义的类型系统与张量运算结合，使向量组合遵循类型约束
- **神经-符号整合（Neuro-Symbolic Integration）**：使用神经网络学习形式语义表示的参数
- **语义解析（Semantic Parsing）**：将自然语言映射到形式语义表示，再由神经网络处理

### 二、组合性原则：从部分到整体

#### 2.1 Frege原则

形式语义学的基石是**组合性原则（Principle of Compositionality）**，也称为Frege原则：

> 复合表达式的意义由其组成部分的意义和组合方式唯一确定。

用公式表示：

$$\llbracket \alpha \beta \rrbracket = f(\llbracket \alpha \rrbracket, \llbracket \beta \rrbracket)$$

其中 $\llbracket \cdot \rrbracket$ 表示语义解释函数，$f$ 是由句法结构决定的组合函数。

这一原则的深刻意义在于：**语义是可计算的**。给定有限的词汇语义和组合规则，我们原则上可以计算任意复杂句子的意义。这正是自然语言的**创造性（Creativity）**——使用有限手段表达无限意义——的形式化基础。

#### 2.2 组合性的挑战

然而，自然语言中存在大量看似违反组合性的现象：

**习语（Idioms）**："kick the bucket"（死亡）的意义不能从"kick"、"the"、"bucket"的意义组合得出。

**隐喻（Metaphor）**："Time is money"的意义不是字面上的"时间=金钱"。

**语境依赖（Context Dependence）**：代词"he"、"it"的意义取决于上下文。

**预设（Presupposition）**："The king of France is bald"预设法国有国王。

形式语义学家发展了多种技术来处理这些挑战：

- **词汇语义的丰富化**：习语作为整体存储在词库中
- **类型提升（Type Lifting）**：允许表达式在需要时改变类型
- **动态语义学（Dynamic Semantics）**：将意义定义为语境的更新函数
- **蒙塔古片段（Montague Fragments）**：承认形式化只能覆盖自然语言的片段

#### 2.3 组合性与RAG的关联

组合性原则对RAG系统设计有重要启示：

**查询理解**：复杂查询的语义可以通过分解和组合来理解。例如，"Who wrote books about AI that were published after 2020?"可以分解为：
- "wrote books"：作者与书籍的关系
- "about AI"：书籍的主题约束
- "published after 2020"：时间约束
这些部分的语义组合起来形成完整的查询语义。

**语义索引**：文档索引可以采用组合式结构，存储实体、关系、属性等语义组件，支持基于组合规则的检索。

**答案生成**：生成的答案应该在语义上与检索到的内容"组合一致"——答案中的各部分应该相互支持，形成连贯的整体语义。

### 三、Lambda演算：语义组合的计算引擎

#### 3.1 Lambda演算基础

**Lambda演算（Lambda Calculus）**是形式语义学的核心计算工具，由逻辑学家Alonzo Church在1930年代发明，后被Montague引入自然语言语义研究。

Lambda演算的核心思想是将函数视为一等公民（First-Class Citizen），可以作为参数传递、作为结果返回、赋值给变量。

**Lambda表达式**的基本形式：$\lambda x . M$

其中 $x$ 是变量，$M$ 是表达式体。这个表达式定义了一个函数：给定 $x$ 的值，返回 $M$ 的值。

例如，$\lambda x . x + 1$ 定义了"后继函数"——接受一个数，返回这个数加1。

**Beta归约（β-reduction）**是Lambda演算的核心计算规则：

$$(\lambda x . M) N \rightarrow M[x := N]$$

将函数 $\lambda x . M$ 应用于参数 $N$，就是在 $M$ 中将所有 $x$ 替换为 $N$。

#### 3.2 自然语言的Lambda表示

让我们用Lambda演算分析更复杂的句子。

**例1：及物动词句"John loves Mary"**

词汇语义：
- $\llbracket John \rrbracket = j$ （实体）
- $\llbracket Mary \rrbracket = m$ （实体）
- $\llbracket loves \rrbracket = \lambda y . \lambda x . love(x, y)$ （类型 $\langle e, \langle e, t \rangle \rangle$）

组合计算：
1. "loves Mary" = $(\lambda y . \lambda x . love(x, y))(m) = \lambda x . love(x, m)$
2. "John loves Mary" = $(\lambda x . love(x, m))(j) = love(j, m)$

最终语义是一个命题：John爱Mary。

**例2：量化句"Every student runs"**

量词"every"的语义是一个二阶函数：

$$\llbracket every \rrbracket = \lambda P . \lambda Q . \forall x (P(x) \rightarrow Q(x))$$

其中 $P$ 是名词的谓词意义，$Q$ 是动词短语的意义。

组合计算：
1. "every student" = $(\lambda P . \lambda Q . \forall x (P(x) \rightarrow Q(x)))(student) = \lambda Q . \forall x (student(x) \rightarrow Q(x))$
2. "Every student runs" = $(\lambda Q . \forall x (student(x) \rightarrow Q(x)))(runs) = \forall x (student(x) \rightarrow runs(x))$

最终语义是：对于所有x，如果x是学生，则x跑步。

#### 3.3 Lambda演算在NLP中的应用

Lambda演算在现代NLP中有多种应用：

**语义解析（Semantic Parsing）**：将自然语言句子转换为Lambda表达式或其他形式语义表示。代表性工作包括：
- CCG语义解析（Combinatory Categorial Grammar）
- Neural Semantic Parsing
- Text-to-SQL

**组合分布式语义学（Compositional Distributional Semantics）**：将Lambda演算的组合结构与向量空间表示结合：

$$\llbracket \text{adj noun} \rrbracket = f(\vec{adj}, \vec{noun})$$

其中 $f$ 是由句法结构决定的张量运算。

**可解释性增强**：使用Lambda表达式作为神经模型的中间表示，提高模型决策的可解释性。

### 四、类型论语义学：更精细的意义结构

#### 4.1 简单类型论的局限

Montague语法使用的简单类型论（Simple Type Theory）虽然强大，但存在一些局限：

- 无法直接表示谓词的内部结构
- 难以处理多态性（Polymorphism）
- 类型系统相对僵硬

现代类型论语义学引入了更丰富的类型系统来解决这些问题。

#### 4.2 依赖类型论

**依赖类型论（Dependent Type Theory）**允许类型依赖于值。例如，"n个元素的向量"可以表示为类型 $Vec(A, n)$，其中 $n$ 是一个具体的数值。

在语言学应用中，依赖类型可以表示：
- 论元结构的精细约束
- 选择性限制（Selectional Restrictions）
- 预设与前提的关系

例如，动词"devour"要求其宾语是可食用的：

$$devour : (x : Entity) \rightarrow Edible(x) \rightarrow (y : Agent) \rightarrow Event$$

这个类型签名表示：devour接受一个实体x（作为宾语），需要证明x是可食用的，再接受一个施事者y，返回一个事件。

#### 4.3 Type-Theoretic Semantics (TTR)

**Type Theory with Records (TTR)**是Robin Cooper发展的类型论框架，特别适合于处理对话和语境依赖现象。

TTR的核心数据结构是**记录类型（Record Type）**：

$$\left[\begin{array}{lcl}
x & : & Ind \\
c_{run} & : & run(x)
\end{array}\right]$$

这个记录类型描述了一种情境：存在一个个体x，且x在跑步。

TTR的优势在于：
- 自然地处理语境和对话状态
- 支持渐进式语义更新
- 与概率和学习方法兼容

#### 4.4 类型论与深度学习的交汇

近年来，类型论与深度学习的结合成为热点：

**类型化神经网络**：将类型约束引入神经网络架构，例如要求模型的输入输出满足特定类型签名。

**可微分类型论**：将类型论的结构引入可微分程序，支持端到端学习。

**类型引导的表示学习**：使用类型信息作为归纳偏置，改善语义表示的学习。

这些方向为认知增强RAG系统提供了新的可能——使用类型论的精确性约束神经模型的语义行为。

### 五、形式语义学在RAG中的应用

#### 5.1 语义解析增强的查询理解

将用户查询转换为形式语义表示，可以实现更精确的查询理解：

```python
"""
基于语义解析的查询理解模块

将自然语言查询转换为结构化语义表示，
支持更精确的检索条件构建。
"""

from dataclasses import dataclass
from typing import List, Optional, Union
from enum import Enum


class SemanticType(Enum):
    """语义类型枚举"""
    ENTITY = "e"           # 实体类型
    PREDICATE = "e->t"     # 一元谓词
    RELATION = "e->e->t"   # 二元关系
    QUANTIFIER = "(e->t)->(e->t)->t"  # 量词
    PROPOSITION = "t"      # 命题


@dataclass
class LambdaTerm:
    """Lambda表达式基类"""
    pass


@dataclass
class Variable(LambdaTerm):
    """变量"""
    name: str
    type: SemanticType


@dataclass
class Constant(LambdaTerm):
    """常量（实体或谓词）"""
    name: str
    type: SemanticType


@dataclass
class Application(LambdaTerm):
    """函数应用"""
    function: LambdaTerm
    argument: LambdaTerm


@dataclass
class Abstraction(LambdaTerm):
    """Lambda抽象"""
    variable: Variable
    body: LambdaTerm


@dataclass
class Quantified(LambdaTerm):
    """量化表达式"""
    quantifier: str  # "forall" or "exists"
    variable: Variable
    scope: LambdaTerm


class SemanticParser:
    """语义解析器
    
    将自然语言查询转换为Lambda演算表示
    """
    
    def __init__(self):
        """初始化解析器，加载词汇语义库"""
        # 词汇到语义的映射
        self.lexicon = {
            # 实体（示例）
            "john": Constant("john", SemanticType.ENTITY),
            "mary": Constant("mary", SemanticType.ENTITY),
            
            # 一元谓词
            "student": Constant("student", SemanticType.PREDICATE),
            "professor": Constant("professor", SemanticType.PREDICATE),
            "book": Constant("book", SemanticType.PREDICATE),
            
            # 二元关系
            "wrote": Constant("wrote", SemanticType.RELATION),
            "about": Constant("about", SemanticType.RELATION),
            "published_in": Constant("published_in", SemanticType.RELATION),
        }
        
        # 量词语义
        self.quantifiers = {
            "every": "forall",
            "all": "forall",
            "some": "exists",
            "a": "exists",
            "any": "exists"
        }
    
    def parse(self, query: str) -> Optional[LambdaTerm]:
        """解析查询为Lambda表达式
        
        Args:
            query: 自然语言查询
            
        Returns:
            Lambda表达式，解析失败返回None
        """
        # 简化实现：基于规则的解析
        # 实际应用中应使用CCG解析器或神经语义解析器
        
        tokens = query.lower().split()
        
        # 尝试匹配常见查询模式
        result = self._try_wh_question(tokens)
        if result:
            return result
        
        result = self._try_yes_no_question(tokens)
        if result:
            return result
        
        return None
    
    def _try_wh_question(self, tokens: List[str]) -> Optional[LambdaTerm]:
        """尝试解析WH问句
        
        模式: "Who/What VP?" -> λx.VP(x)
        """
        if not tokens:
            return None
        
        if tokens[0] in ["who", "what"]:
            # 简化：提取主要谓词
            for token in tokens[1:]:
                if token in self.lexicon:
                    pred = self.lexicon[token]
                    if pred.type == SemanticType.PREDICATE:
                        x = Variable("x", SemanticType.ENTITY)
                        return Abstraction(x, Application(pred, x))
        
        return None
    
    def _try_yes_no_question(self, tokens: List[str]) -> Optional[LambdaTerm]:
        """尝试解析是非问句"""
        # 简化实现
        return None
    
    def to_retrieval_query(self, term: LambdaTerm) -> dict:
        """将Lambda表达式转换为检索查询
        
        Args:
            term: Lambda表达式
            
        Returns:
            结构化检索查询
        """
        if isinstance(term, Abstraction):
            # 开放查询：找满足条件的实体
            return {
                "type": "open_query",
                "variable": term.variable.name,
                "constraint": self._term_to_constraint(term.body)
            }
        elif isinstance(term, Quantified):
            # 量化查询
            return {
                "type": "quantified_query",
                "quantifier": term.quantifier,
                "variable": term.variable.name,
                "scope": self._term_to_constraint(term.scope)
            }
        else:
            return {"type": "unknown"}
    
    def _term_to_constraint(self, term: LambdaTerm) -> dict:
        """将Lambda项转换为约束表示"""
        if isinstance(term, Application):
            return {
                "predicate": self._get_predicate_name(term.function),
                "arguments": [self._get_argument(term.argument)]
            }
        elif isinstance(term, Constant):
            return {"constant": term.name}
        elif isinstance(term, Variable):
            return {"variable": term.name}
        else:
            return {}
    
    def _get_predicate_name(self, term: LambdaTerm) -> str:
        """获取谓词名称"""
        if isinstance(term, Constant):
            return term.name
        return "unknown"
    
    def _get_argument(self, term: LambdaTerm) -> str:
        """获取参数表示"""
        if isinstance(term, Constant):
            return term.name
        elif isinstance(term, Variable):
            return f"?{term.name}"
        return "unknown"


# 使用示例
def demo_semantic_parsing():
    """演示语义解析"""
    parser = SemanticParser()
    
    queries = [
        "Who is a student?",
        "What books did John write?",
        "Who wrote books about AI?"
    ]
    
    for query in queries:
        print(f"\n查询: {query}")
        term = parser.parse(query)
        if term:
            retrieval_query = parser.to_retrieval_query(term)
            print(f"检索查询: {retrieval_query}")
        else:
            print("解析失败")


if __name__ == "__main__":
    demo_semantic_parsing()
```

```python
class Type(ABC):
    """类型基类"""
    @abstractmethod
    def __str__(self) -> str:
        pass


@dataclass
class AtomicType(Type):
    """原子类型"""
    name: str
    
    def __str__(self) -> str:
        return self.name


@dataclass
class FunctionType(Type):
    """函数类型"""
    domain: Type
    codomain: Type
    
    def __str__(self) -> str:
        return f"({self.domain} -> {self.codomain})"


# 预定义类型
ENTITY = AtomicType("Entity")
PROPOSITION = AtomicType("Prop")
EVENT = AtomicType("Event")
TIME = AtomicType("Time")


# 知识库条目
@dataclass
class Entity:
    """实体"""
    id: str
    name: str
    type: Type
    attributes: Dict[str, Any] = field(default_factory=dict)


@dataclass
class Relation:
    """关系"""
    name: str
    arg_types: List[Type]
    return_type: Type = PROPOSITION


@dataclass
class Fact:
    """事实（关系实例）"""
    relation: str
    arguments: List[str]  # 实体ID列表
    confidence: float = 1.0
    source: Optional[str] = None


class TypedKnowledgeBase:
    """类型化知识库
    
    支持类型检查的知识存储和检索
    """
    
    def __init__(self):
        self.entities: Dict[str, Entity] = {}
        self.relations: Dict[str, Relation] = {}
        self.facts: List[Fact] = []
        self.type_hierarchy: Dict[str, Set[str]] = {}  # 子类型关系
    
    def define_subtype(self, subtype: str, supertype: str):
        """定义子类型关系
        
        Args:
            subtype: 子类型名
            supertype: 父类型名
        """
        if subtype not in self.type_hierarchy:
            self.type_hierarchy[subtype] = set()
        self.type_hierarchy[subtype].add(supertype)
    
    def is_subtype(self, t1: Type, t2: Type) -> bool:
        """检查t1是否是t2的子类型
        
        Args:
            t1: 待检查类型
            t2: 目标类型
            
        Returns:
            是否为子类型
        """
        if isinstance(t1, AtomicType) and isinstance(t2, AtomicType):
            if t1.name == t2.name:
                return True
            if t1.name in self.type_hierarchy:
                if t2.name in self.type_hierarchy[t1.name]:
                    return True
                # 传递性检查
                for super_t in self.type_hierarchy[t1.name]:
                    if self.is_subtype(AtomicType(super_t), t2):
                        return True
        return False
    
    def add_entity(self, entity: Entity) -> bool:
        """添加实体
        
        Args:
            entity: 实体对象
            
        Returns:
            添加是否成功
        """
        self.entities[entity.id] = entity
        return True
    
    def add_relation(self, relation: Relation) -> bool:
        """定义关系
        
        Args:
            relation: 关系定义
            
        Returns:
            添加是否成功
        """
        self.relations[relation.name] = relation
        return True
    
    def add_fact(self, fact: Fact) -> bool:
        """添加事实，进行类型检查
        
        Args:
            fact: 事实对象
            
        Returns:
            添加是否成功（通过类型检查）
        """
        # 检查关系是否存在
        if fact.relation not in self.relations:
            print(f"类型错误：未定义的关系 {fact.relation}")
            return False
        
        relation = self.relations[fact.relation]
        
        # 检查参数数量
        if len(fact.arguments) != len(relation.arg_types):
            print(f"类型错误：参数数量不匹配")
            return False
        
        # 检查每个参数的类型
        for arg_id, expected_type in zip(fact.arguments, relation.arg_types):
            if arg_id not in self.entities:
                print(f"类型错误：未知实体 {arg_id}")
                return False
            
            entity = self.entities[arg_id]
            if not self.is_subtype(entity.type, expected_type):
                print(f"类型错误：{arg_id} 的类型 {entity.type} 不是 {expected_type} 的子类型")
                return False
        
        self.facts.append(fact)
        return True
    
    def query(
        self, 
        relation: str, 
        constraints: Dict[int, str] = None
    ) -> List[Fact]:
        """查询事实
        
        Args:
            relation: 关系名
            constraints: 参数位置到值的约束，如 {0: "john"}
            
        Returns:
            匹配的事实列表
        """
        constraints = constraints or {}
        results = []
        
        for fact in self.facts:
            if fact.relation != relation:
                continue
            
            match = True
            for pos, value in constraints.items():
                if pos >= len(fact.arguments) or fact.arguments[pos] != value:
                    match = False
                    break
            
            if match:
                results.append(fact)
        
        return results


# 使用示例
def demo_typed_kb():
    """演示类型化知识库"""
    kb = TypedKnowledgeBase()
    
    # 定义类型层次
    PERSON = AtomicType("Person")
    AUTHOR = AtomicType("Author")
    BOOK = AtomicType("Book")
    TOPIC = AtomicType("Topic")
    
    kb.define_subtype("Person", "Entity")
    kb.define_subtype("Author", "Person")
    kb.define_subtype("Book", "Entity")
    kb.define_subtype("Topic", "Entity")
    
    # 定义关系
    kb.add_relation(Relation("wrote", [AUTHOR, BOOK]))
    kb.add_relation(Relation("about", [BOOK, TOPIC]))
    kb.add_relation(Relation("published_year", [BOOK, AtomicType("Year")]))
    
    # 添加实体
    kb.add_entity(Entity("john", "John Smith", AUTHOR))
    kb.add_entity(Entity("book1", "Introduction to AI", BOOK))
    kb.add_entity(Entity("ai", "Artificial Intelligence", TOPIC))
    kb.add_entity(Entity("2023", "2023", AtomicType("Year")))
    
    # 添加事实（带类型检查）
    print("添加事实（类型检查）:")
    print(f"  wrote(john, book1): {kb.add_fact(Fact('wrote', ['john', 'book1']))}")
    print(f"  about(book1, ai): {kb.add_fact(Fact('about', ['book1', 'ai']))}")
    
    # 类型错误示例
    print(f"  wrote(book1, john): {kb.add_fact(Fact('wrote', ['book1', 'john']))}")  # 类型错误
    
    # 查询
    print("\n查询 wrote(john, ?):")
    for fact in kb.query("wrote", {0: "john"}):
        book = kb.entities[fact.arguments[1]]
        print(f"  {book.name}")
```

#### 5.3 组合式语义检索

利用组合性原则设计分层检索策略：

```python
"""
组合式语义检索

基于形式语义学的组合性原则，
将复杂查询分解为语义组件，分层检索后组合结果。

时间复杂度分析：
- 查询分解：O(q)，q为查询长度
- 组件检索：O(k * log n)，k为组件数，n为索引规模
- 结果组合：O(r^k)，r为每组件结果数（需剪枝优化）

运行时间估算：
- 简单查询（2-3组件）：<100ms
- 复杂查询（5+组件）：200-500ms（需缓存优化）
"""

from dataclasses import dataclass
from typing import List, Dict, Set, Tuple, Optional
from abc import ABC, abstractmethod
import numpy as np


@dataclass
class SemanticComponent:
    """语义组件
    
    Attributes:
        type: 组件类型（entity, predicate, relation, quantifier）
        content: 组件内容
        dependencies: 依赖的其他组件
    """
    type: str
    content: str
    dependencies: List[str] = None
    
    def __post_init__(self):
        if self.dependencies is None:
            self.dependencies = []


@dataclass
class RetrievalResult:
    """检索结果
    
    Attributes:
        doc_id: 文档ID
        score: 相关度分数
        matched_components: 匹配的语义组件
        snippet: 匹配文本片段
    """
    doc_id: str
    score: float
    matched_components: List[str]
    snippet: str


class ComponentRetriever(ABC):
    """组件检索器基类"""
    
    @abstractmethod
    def retrieve(
        self, 
        component: SemanticComponent, 
        top_k: int = 10
    ) -> List[Tuple[str, float]]:
        """检索匹配组件的文档
        
        Args:
            component: 语义组件
            top_k: 返回结果数
            
        Returns:
            (文档ID, 分数)列表
        """
        pass


class VectorRetriever(ComponentRetriever):
    """基于向量的组件检索器"""
    
    def __init__(self, index, embed_model):
        self.index = index
        self.embed_model = embed_model
    
    def retrieve(
        self, 
        component: SemanticComponent, 
        top_k: int = 10
    ) -> List[Tuple[str, float]]:
        """向量检索实现"""
        # 获取组件文本的嵌入
        query_vector = self.embed_model.encode(component.content)
        
        # 在索引中检索
        scores, doc_ids = self.index.search(query_vector, top_k)
        
        return list(zip(doc_ids, scores))


class CompositionalRetriever:
    """组合式检索器
    
    将查询分解为语义组件，分别检索后组合结果
    """
    
    def __init__(self, component_retriever: ComponentRetriever):
        """初始化
        
        Args:
            component_retriever: 组件检索器
        """
        self.component_retriever = component_retriever
        self.combination_strategies = {
            "intersection": self._intersect_results,
            "union": self._union_results,
            "weighted": self._weighted_combine
        }
    
    def decompose_query(self, query: str) -> List[SemanticComponent]:
        """将查询分解为语义组件
        
        Args:
            query: 自然语言查询
            
        Returns:
            语义组件列表
        """
        # 简化实现：基于关键词和模式匹配
        # 实际应使用语义解析器
        
        components = []
        
        # 识别实体提及
        # 这里使用简化的启发式方法
        words = query.split()
        
        # 识别疑问词确定查询类型
        if words[0].lower() in ["who", "what", "which"]:
            components.append(SemanticComponent(
                type="query_type",
                content=words[0].lower()
            ))
        
        # 提取主要谓词和实体（简化）
        for i, word in enumerate(words):
            if word[0].isupper() and i > 0:  # 可能是实体
                components.append(SemanticComponent(
                    type="entity",
                    content=word
                ))
        
        # 提取关系词
        relation_words = ["wrote", "published", "about", "created", "developed"]
        for word in words:
            if word.lower() in relation_words:
                components.append(SemanticComponent(
                    type="relation",
                    content=word.lower()
                ))
        
        # 如果分解失败，返回整个查询作为单一组件
        if not components:
            components.append(SemanticComponent(
                type="full_query",
                content=query
            ))
        
        return components
    
    def retrieve(
        self, 
        query: str, 
        strategy: str = "weighted",
        top_k: int = 10
    ) -> List[RetrievalResult]:
        """执行组合式检索
        
        Args:
            query: 自然语言查询
            strategy: 结果组合策略
            top_k: 最终返回结果数
            
        Returns:
            检索结果列表
        """
        # 1. 分解查询
        components = self.decompose_query(query)
        print(f"查询分解为 {len(components)} 个组件")
        
        # 2. 分别检索每个组件
        component_results: Dict[str, List[Tuple[str, float]]] = {}
        for comp in components:
            results = self.component_retriever.retrieve(comp, top_k=top_k * 2)
            component_results[comp.content] = results
            print(f"  组件 '{comp.content}' 检索到 {len(results)} 个结果")
        
        # 3. 组合结果
        combine_fn = self.combination_strategies.get(strategy, self._weighted_combine)
        combined = combine_fn(component_results, components)
        
        # 4. 排序并返回top_k
        combined.sort(key=lambda x: x.score, reverse=True)
        return combined[:top_k]
    
    def _intersect_results(
        self, 
        component_results: Dict[str, List[Tuple[str, float]]],
        components: List[SemanticComponent]
    ) -> List[RetrievalResult]:
        """交集策略：只返回所有组件都匹配的文档"""
        if not component_results:
            return []
        
        # 获取所有文档ID集合
        doc_sets = [
            set(doc_id for doc_id, _ in results)
            for results in component_results.values()
        ]
        
        # 计算交集
        common_docs = doc_sets[0]
        for doc_set in doc_sets[1:]:
            common_docs &= doc_set
        
        # 构建结果
        results = []
        for doc_id in common_docs:
            scores = []
            matched = []
            for comp_name, comp_results in component_results.items():
                for did, score in comp_results:
                    if did == doc_id:
                        scores.append(score)
                        matched.append(comp_name)
                        break
            
            results.append(RetrievalResult(
                doc_id=doc_id,
                score=np.mean(scores),
                matched_components=matched,
                snippet=""
            ))
        
        return results
    
    def _union_results(
        self, 
        component_results: Dict[str, List[Tuple[str, float]]],
        components: List[SemanticComponent]
    ) -> List[RetrievalResult]:
        """并集策略：返回任意组件匹配的文档"""
        doc_scores: Dict[str, List[float]] = {}
        doc_matched: Dict[str, List[str]] = {}
        
        for comp_name, comp_results in component_results.items():
            for doc_id, score in comp_results:
                if doc_id not in doc_scores:
                    doc_scores[doc_id] = []
                    doc_matched[doc_id] = []
                doc_scores[doc_id].append(score)
                doc_matched[doc_id].append(comp_name)
        
        results = []
        for doc_id, scores in doc_scores.items():
            results.append(RetrievalResult(
                doc_id=doc_id,
                score=np.max(scores),  # 使用最高分
                matched_components=doc_matched[doc_id],
                snippet=""
            ))
        
        return results
    
    def _weighted_combine(
        self, 
        component_results: Dict[str, List[Tuple[str, float]]],
        components: List[SemanticComponent]
    ) -> List[RetrievalResult]:
        """加权组合策略：根据组件重要性加权"""
        # 组件类型权重
        type_weights = {
            "entity": 1.5,
            "relation": 1.2,
            "predicate": 1.0,
            "query_type": 0.5,
            "full_query": 1.0
        }
        
        # 构建组件到权重的映射
        comp_weights = {}
        for comp in components:
            weight = type_weights.get(comp.type, 1.0)
            comp_weights[comp.content] = weight
        
        # 累加加权分数
        doc_scores: Dict[str, float] = {}
        doc_matched: Dict[str, List[str]] = {}
        total_weight = sum(comp_weights.values())
        
        for comp_name, comp_results in component_results.items():
            weight = comp_weights.get(comp_name, 1.0)
            for doc_id, score in comp_results:
                if doc_id not in doc_scores:
                    doc_scores[doc_id] = 0
                    doc_matched[doc_id] = []
                doc_scores[doc_id] += score * weight / total_weight
                if comp_name not in doc_matched[doc_id]:
                    doc_matched[doc_id].append(comp_name)
        
        results = []
        for doc_id, score in doc_scores.items():
            results.append(RetrievalResult(
                doc_id=doc_id,
                score=score,
                matched_components=doc_matched[doc_id],
                snippet=""
            ))
        
        return results


# 演示用的模拟检索器
class MockRetriever(ComponentRetriever):
    """模拟检索器，用于演示"""
    
    def __init__(self):
        self.mock_data = {
            "ai": [("doc1", 0.9), ("doc2", 0.8), ("doc3", 0.7)],
            "wrote": [("doc1", 0.85), ("doc4", 0.75)],
            "john": [("doc1", 0.95), ("doc5", 0.6)],
            "who": [("doc1", 0.5), ("doc2", 0.5), ("doc3", 0.5)],
        }
    
    def retrieve(
        self, 
        component: SemanticComponent, 
        top_k: int = 10
    ) -> List[Tuple[str, float]]:
        key = component.content.lower()
        return self.mock_data.get(key, [("doc0", 0.1)])[:top_k]


# 使用示例
def demo_compositional_retrieval():
    """演示组合式检索"""
    mock_retriever = MockRetriever()
    comp_retriever = CompositionalRetriever(mock_retriever)
    
    query = "Who wrote books about AI?"
    print(f"查询: {query}\n")
    
    results = comp_retriever.retrieve(query, strategy="weighted", top_k=5)
    
    print("\n检索结果:")
    for i, result in enumerate(results):
        print(f"  {i+1}. {result.doc_id} (score: {result.score:.3f})")
        print(f"     匹配组件: {result.matched_components}")


if __name__ == "__main__":
    demo_compositional_retrieval()
```
