## 第一节 对话结构理论基础

### 一、会话分析的核心概念

**会话分析（Conversation Analysis, CA）**起源于Sacks、Schegloff和Jefferson的民族方法学研究，关注自然会话的组织结构。

**核心概念**：

**话轮（Turn）**：
一个说话者连续说话的单位。

**话轮转换（Turn-taking）**：
说话权在参与者之间的转移。

**相邻对（Adjacency Pair）**：
构成会话基本单位的两个相邻话轮。

| 第一部分 | 第二部分（优先） | 第二部分（非优先） |
|---------|----------------|------------------|
| 问题 | 回答 | 拒绝回答 |
| 请求 | 接受 | 拒绝 |
| 邀请 | 接受 | 拒绝 |
| 评价 | 同意 | 不同意 |

### 二、对话行为理论

**对话行为（Dialogue Acts）**是对话中的功能单位，对应言语行为理论在对话语境中的应用。

**DAMSL标注体系**：

| 类别 | 对话行为 |
|------|----------|
| 前向功能 | 陈述、问题、指令、承诺 |
| 后向功能 | 接受、拒绝、回答、确认 |
| 信息层 | 信息请求、信息提供 |
| 通讯管理 | 开场、结束、修复 |

### 三、任务型对话结构

任务型对话（Task-oriented Dialogue）具有特定的结构模式：

**槽位填充（Slot Filling）**：
```
领域：餐厅预订
槽位：
  - restaurant_name: ?
  - date: ?
  - time: ?
  - party_size: ?
  - cuisine: ?
```

**对话状态（Dialogue State）**：
```
{
  "restaurant_name": "金龙餐厅",
  "date": "明天",
  "time": "19:00",
  "party_size": 4,
  "cuisine": null
}
```

## 第二节 对话状态追踪SOTA

### 一、FnCTOD：函数调用范式

Li等人（ACL 2024, arXiv:2402.10466）的**FnCTOD**将零样本对话状态追踪重构为**函数调用任务**。

**核心思想**：

```python
# 传统DST
input: "我想预订明天晚上7点的餐厅，4个人"
output: {"date": "明天", "time": "19:00", "party_size": 4}

# FnCTOD函数调用
function_call: book_restaurant(
    date="明天",
    time="19:00", 
    party_size=4
)
```

**实验结果**：

| 模型 | 方法 | JGA提升 |
|------|------|---------|
| GPT-4 | 函数调用 | **+14%** |
| GPT-3.5 | 函数调用 | **+4.8%** |
| LLaMA2-13B | 函数调用微调 | 达到ChatGPT水平 |

**关键发现**：7B/13B模型通过函数调用提示超越ChatGPT先前SOTA。

**GitHub**：https://github.com/facebookresearch/FnCTOD

### 二、LUAS：LLM用户智能体模拟

Wang等人（ACL 2024）的**LUAS**通过LLM支持的用户智能体模拟增强DST。

**两阶段微调**：
1. 使用GPT-4生成模拟对话
2. 在LLaMA 2上微调

**效果**：超越仅用真实数据训练的基线。

**GitHub**：https://github.com/ParticleMedia/LUAS

### 三、DualLoRA：零样本跨领域DST

arXiv:2407.21633的**DualLoRA**实现零样本跨领域DST。

**双LoRA组件**：
- **语境LoRA**：处理对话语境
- **提示LoRA**：优化任务提示

**优势**：无推理延迟开销。

**GitHub**：https://github.com/suntea233/DualLoRA

### 一、MultiWOZ概述

**MultiWOZ**是多领域任务型对话的标准基准。

**版本演进**：

| 版本 | 年份 | 改进 |
|------|------|------|
| 2.0 | 2018 | 原始版本 |

**数据规模**：

## 第四节 口语对话理解

### 一、SpokenWOZ数据集

Si等人（NeurIPS 2023 Datasets Track, arXiv:2305.13040）发布的**SpokenWOZ**是口语任务型对话的里程碑数据集。

**规模**：
- 8个领域
- **203,000轮次**
- 5,700对话
- **249小时音频**

**关键发现**：
- 最佳DST模型仅达**25.65% JGA**
- 与书面对话存在**显著差距**
- 最佳端到端模型任务完成率52.1%

**网站**：https://spokenwoz.github.io/SpokenWOZ-github.io/

### 二、ASR错误对对话理解的影响

**SIGDIAL 2024**的研究通过噪声表示学习增强对话语音识别：

| 条件 | WER降低 |
|------|---------|
| 整体 | **24%相对降低** |
| 0dB SNR（极端噪声） | **31%相对降低** |

**关键词感知ASR错误增强**（arXiv:2409.06263）：
- 实现**95.4%目标关键词错误多样性**
- DST准确率从45.76%提升至**51.12%**

## 第五节 多轮对话RAG

### 一、mtRAG基准

TACL 2025发布的**mtRAG**是首个多轮对话RAG基准（arXiv:2501.03468）。

**规模**：
- 110个对话
- 平均7.7轮
- 842个任务

**特点**：
- **主动检索**：对话中段落变化
- **长形式答案**：需要综合多源信息
- **不可回答问题**：检测无法回答的情况

**关键发现**：
- 即使SOTA LLM RAG系统也存在困难
- 后续轮次和非独立问题需要强检索支持

### 二、DH-RAG：动态历史语境

Zhang等人（arXiv:2502.13847）的**DH-RAG**是多轮对话RAG的核心方法。

**两个核心模块**：

**历史学习查询重构**：
```python
def history_aware_query_rewrite(current_query, history):
    """基于历史的查询重写"""
    # 识别指代和省略
    resolved_query = resolve_references(current_query, history)
    # 融合历史上下文
    enriched_query = enrich_with_context(resolved_query, history)
    return enriched_query
```

**动态历史信息更新**：
```python
def dynamic_history_update(history, new_turn, relevance_threshold):
    """动态更新历史信息"""
    # 评估每个历史轮次的相关性
    for turn in history:
        turn.relevance = compute_relevance(turn, new_turn)
    
    # 过滤低相关历史
    filtered_history = [t for t in history if t.relevance > relevance_threshold]
    
    # 添加新轮次
    filtered_history.append(new_turn)
    
    return filtered_history
```

**三种策略**：
1. 历史查询聚类
2. 层级匹配
3. 思维链追踪

### 三、CID-GraphRAG

arXiv:2506.19385的**CID-GraphRAG**整合意图转换图与语义相似性检索。

**核心创新**：
- 结合对话RAG与图RAG
- 实现结构化对话流推理
- 意图转换建模

## 第六节 对话结构在RAG中的应用

### 一、槽位基础的查询构建

```python
def slot_based_query_construction(dialogue_state):
    """基于槽位的查询构建"""
    
    queries = []
    
    # 为每个已填充槽位构建子查询
    for slot, value in dialogue_state.items():
        if value is not None:
            queries.append(f"{slot}: {value}")
    
    # 组合查询
    combined_query = " AND ".join(queries)
    
    return combined_query

# 示例
state = {
    "restaurant_name": "金龙餐厅",
    "cuisine": "中餐",
    "price_range": "中等"
}
# 输出: "restaurant_name: 金龙餐厅 AND cuisine: 中餐 AND price_range: 中等"
```

### 二、多轮上下文维护

| 挑战 | 解决方案 | 技术 |
|------|---------|------|
| 指代消解 | 替换代词为先行词 | 共指消解 |
| 省略恢复 | 补全省略成分 | 句法分析 |
| 话题追踪 | 维护话题栈 | 对话状态追踪 |
| 历史相关性 | 动态过滤历史 | DH-RAG |

### 三、函数调用风格的RAG

```python
def function_call_rag(user_utterance, dialogue_state):
    """函数调用风格的RAG"""
    
    # 解析为函数调用
    function_call = parse_as_function_call(user_utterance)
    
    if function_call.name == "search_restaurant":
        # 构建检索查询
        query = build_restaurant_query(function_call.args)
        results = retrieve(query)
        
    elif function_call.name == "book_restaurant":
        # 执行预订
        booking = execute_booking(function_call.args)
        results = format_booking_confirmation(booking)
    
    return results
```
