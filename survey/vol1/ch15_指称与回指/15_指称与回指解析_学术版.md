## 第一节 指称理论基础

### 一、指称的哲学背景

**指称（Reference）**是语言与世界连接的核心机制。语言表达式如何指向世界中的实体，是语言哲学和语义学的核心问题。

**弗雷格的意义理论**：
- **涵义（Sinn）**：表达式的认知内容
- **指称（Bedeutung）**：表达式所指向的对象

> "晨星"和"昏星"涵义不同，但指称相同（都是金星）

**指称表达式类型**：

| 类型 | 示例 | 特点 |
|------|------|------|
| **专有名词** | "北京"、"李明" | 直接指称 |
| **确定描述语** | "中国的首都" | 通过描述确定指称 |
| **代词** | "他"、"她"、"它" | 依赖语境 |
| **指示语** | "这个"、"那里" | 依赖说话语境 |

### 二、回指现象

**回指（Anaphora）**是指称表达式依赖先前提及的实体来确定其指称的现象。

**先行词（Antecedent）**：被回指的表达式
**回指语（Anaphor）**：依赖先行词的表达式

```
[李明]ᵢ 走进了房间。[他]ᵢ 看起来很疲惫。
先行词：李明
回指语：他
共指关系：i
```

**回指类型**：

| 类型 | 示例 |
|------|------|
| **代词回指** | 李明...他... |
| **零回指** | 李明进来，Ø坐下了 |
| **名词短语回指** | 总统...这位领导人... |
| **桥接回指** | 房子...门... |

### 三、共指与共指链

**共指（Coreference）**：两个或多个表达式指向同一实体。

**共指链（Coreference Chain）**：文档中所有共指表达式的集合。

```
[张伟]₁ 是一名工程师。[他]₁ 在 [一家科技公司]₂ 工作。
[这家公司]₂ 位于北京。[张伟]₁ 每天骑车上班。

共指链1：{张伟, 他, 张伟}
共指链2：{一家科技公司, 这家公司}
```

## 第二节 CRAC共享任务与CorPipe系统

### 一、CRAC 2024第三届共享任务

Novák等人（EMNLP 2024 CRAC Workshop, arXiv:2410.15949）组织的**CRAC 2024**是多语言共指消解的权威评测。

**数据集**：CorefUD 1.2
- 21个数据集
- 15种语言
- 新增历史语言：古希腊语、古希伯来语、古教会斯拉夫语

**2024新目标**：
- 从**原始文本**预测零回指空节点
- 空节点不作为输入提供，需要系统自动预测

**主要指标**：CoNLL F1（头匹配，排除单例）

### 二、CorPipe获胜系统

Straka（EMNLP 2024 CRAC, arXiv:2410.02756）的**CorPipe**实现**三连冠**。

**两种方法**：

**两阶段方法**（领先3.9个百分点）：
1. 使用预训练编码器预测空节点
2. 进行共指消解

**单阶段方法**（领先2.8个百分点）：
- 联合生成空节点、提及和共指链

**技术特点**：
- 基于**mT5-large**多语言模型
- 语言无关设计
- 支持最长**2560子词**的上下文窗口

**GitHub**：https://github.com/ufal/crac2024-corpipe
**模型**：https://hdl.handle.net/11234/1-5672

### 三、CRAC 2025 LLM赛道

Novák等人（arXiv:2509.17796）组织的**CRAC 2025**首次设立LLM专用赛道。

**背景**：先前研究显示LLM难以处理共指且无法超越专门系统。

**挑战**：
- 提及范围的异构定义
- 零回指重构
- 关系类型的数据差异

## 第三节 LLM与共指解析

### 一、LLM共指幻觉问题

Gan等人（arXiv:2509.11466）研究了LLM在共指消解中的**幻觉问题**。

**问题描述**：
```
输入：使用文档模板方法解析共指
期望输出：正确标注共指的文档
实际输出：LLM生成错误文本（幻觉）
```

**幻觉类型**：
- 生成原文中不存在的实体
- 错误合并不同实体
- 遗漏共指关系

**发现**：
- 文档模板优于QA模板
- 但依赖**无幻觉假设**
- 幻觉在语言复杂文本中尤为常见

### 二、消除幻觉的方法

**反向训练+联合推理**：

- 多轮生成和验证
- 每轮消除检测到的幻觉

### 三、CorefInst：指令微调方法

Pamay Arslan等人（arXiv:2509.17505）的**CorefInst**探索共指消解的指令微调。

**特点**：
- 处理省略主语语言中的零提及
- 指令格式适配不同共指任务

## 第四节 RAG中的共指应用

### 一、共指消解预处理

arXiv:2507.07847提出**LLM驱动的RAG共指消解函数**。

**方法**：
```python
def coref_enhanced_rag(document, llm="gpt-4o-mini"):
    """共指增强的RAG预处理"""
    
    # 使用LLM进行共指消解
    coref_chains = llm.resolve_coreference(document)
    
    # 将代词替换为显式先行词
    resolved_document = replace_pronouns(document, coref_chains)
    
    # 索引解析后的文档
    index(resolved_document)
    
    return resolved_document
```

**测试配置**：
- 嵌入模型：e5-large-v2, stella, bge-large, gte-modernbert
- LLM：Llama3.2-3B, Qwen2.5等

**发现**：共指消解通过使语义关系显式化，**显著提升检索和QA质量**。

### 二、CLAP：共指链增强段落检索

arXiv:2508.06941的**CLAP（Coreference-Linked Augmentation for Passage Retrieval）**：

**三阶段管道**：

1. **语义分块**：按语义边界分割文档
2. **共指消解**：识别跨块共指链
3. **伪查询生成**：为每个块生成查询

**代词显式化**：
```
原始块："他说公司将在下季度发布新产品"
显式化后："李明说华为将在下季度发布新产品"
```

**双视图检索**：
- 全局视图：查询-段落匹配
- 局部视图：查询-伪查询匹配

### 三、LINK-KG：图RAG实体一致性

arXiv:2510.26486的**LINK-KG**用于知识图谱构建的模块化LLM引导共指消解管道。

**核心创新**：**类型特定提示缓存**
- 为不同实体类型设计专门提示
- 跨文档块追踪实体
- 维护实体一致性

**效果**：
- **45.21%节点重复减少**
- 32.22%噪声节点降低

## 第五节 零回指与桥接回指

### 一、零回指检测

**零回指（Zero Anaphora）**在省略主语语言（如中文、日语、韩语）中尤为常见。

```
中文示例：
[张三]ᵢ 进了门，Øᵢ 脱了外套，Øᵢ 坐了下来。
（省略了两个"张三"）
```

**CRAC 2024新任务**：
- 从原始文本预测零回指位置
- 不提供空节点作为输入

**CorPipe方法**：
- 联合预测空节点位置和共指关系
- 使用mT5-large的生成能力

### 二、桥接回指

**桥接回指（Bridging Anaphora）**不是直接共指，而是通过关联关系连接。

```
我走进了[房子]ᵢ。[门]ⱼ 开着。
关系：门是房子的部分（part-of）
```

**CRAC 2024最佳论文**（Levine & Zeldes）：
- 比较ARRAU和GUM语料库桥接标注方案
- 训练XGBoost分类器达到**0.67 F-score**

### 三、BookCoref：长文档共指

arXiv:2507.12075的**BookCoref**是首个书籍级共指消解数据集。

**挑战**：
- LLM需要**300,000+令牌**的上下文窗口
- 幻觉和模糊提及匹配是关键挑战

**评估系统**：
- BookNLP
- Longdoc
- Dual cache
- Maverick

## 第六节 共指解析在RAG中的应用

### 一、检索前共指预处理

```python
class CorefPreprocessor:
    def __init__(self, coref_model):
        self.coref_model = coref_model
    
    def preprocess_for_indexing(self, document):
        """索引前的共指预处理"""
        
        # 检测共指链
        chains = self.coref_model.predict(document)
        
        # 为每个提及添加先行词信息
        enriched_doc = self.enrich_with_antecedents(document, chains)
        
        return enriched_doc
    
    def enrich_with_antecedents(self, document, chains):
        """用先行词信息丰富文档"""
        for chain in chains:
            head_mention = chain[0]  # 先行词
            for mention in chain[1:]:
                # 在代词后添加先行词注释
                document = self.annotate(document, mention, head_mention)
        return document
```

### 二、跨文档实体追踪

| 场景 | 挑战 | 解决方案 |
|------|------|---------|
| 多文档检索 | 同一实体不同称呼 | 实体链接+共指 |
| 图RAG构建 | 节点重复 | LINK-KG类型缓存 |
| 长文档QA | 远距离共指 | 层级处理 |
