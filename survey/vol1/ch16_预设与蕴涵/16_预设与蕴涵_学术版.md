## 第一节 预设理论基础

### 一、预设的定义与性质

**预设（Presupposition）**是说话者在发出话语时假定为真的背景信息。

**经典示例**：

```
话语："法国现任国王是秃头。"
预设：法国有一位现任国王。（实际为假）
断言：那位国王是秃头。
```

**预设的核心性质**：

**否定下的保持性**：
```
肯定句："约翰戒烟了。"
否定句："约翰没有戒烟。"
共同预设：约翰以前抽烟。
```

**疑问下的保持性**：
```
陈述："玛丽后悔嫁给了约翰。"
疑问："玛丽后悔嫁给约翰吗？"
共同预设：玛丽嫁给了约翰。
```

### 二、预设触发词

**预设触发词（Presupposition Triggers）**是引发预设的语言形式：

| 触发词类型 | 示例 | 预设 |
|-----------|------|------|
| **事实动词** | "知道"、"意识到" | 补语为真 |
| **反复词** | "又"、"再" | 先前发生过 |
| **状态变化动词** | "戒"、"停止" | 先前状态 |
| **定描述语** | "那个X" | X存在且唯一 |
| **时间从句** | "在...之前/后" | 事件发生 |
| **分裂句** | "是X做了Y" | Y发生了 |

### 三、预设投射问题

**预设投射（Presupposition Projection）**：复杂句中预设如何传递到整体句子。

```
"如果约翰以前抽烟，他戒烟了。"
→ 后件预设"约翰以前抽烟"被前件满足
→ 整句不预设"约翰以前抽烟"（被过滤）
```

**预设调适（Presupposition Accommodation）**：
听者在预设不满足时自动接受预设为真的过程。

## 第二节 文本蕴涵理论

### 一、蕴涵的定义

**文本蕴涵（Textual Entailment）**：如果文本T为真则假设H必然为真，则T蕴涵H。

```
T: "所有鸟都会飞。麻雀是鸟。"
H: "麻雀会飞。"
关系: T ⊨ H（T蕴涵H）
```

**蕴涵与预设的区别**：

| 特性 | 蕴涵 | 预设 |
|------|------|------|
| 否定下 | 消失 | 保持 |
| 语义地位 | 前景信息 | 背景信息 |
| 真值依赖 | T真→H真 | 说话者假定为真 |

### 二、自然语言推理（NLI）

**NLI任务**：判断前提-假设对之间的关系。

| 关系 | 定义 |
|------|------|
| **蕴涵（Entailment）** | 前提为真则假设为真 |
| **矛盾（Contradiction）** | 前提为真则假设为假 |
| **中立（Neutral）** | 无法确定假设真假 |

**主要数据集**：

| 数据集 | 规模 | 特点 |
|--------|------|------|
| SNLI | 570K | 图片描述来源 |
| MNLI | 433K | 多体裁 |
| ANLI | 163K | 对抗性构建 |
| XNLI | 112K | 跨语言 |

## 第三节 LLM处理预设的能力评估

### 一、UPHILL基准

Kaur等人（ACL 2024 Findings, DOI:10.18653/v1/2024.findings-acl.850）的研究评估LLM处理预设的能力。

**数据集**：UPHILL（包含不同程度预设的健康查询）

**关键发现**：

| 声明类型 | LLM同意率 |
|---------|----------|
| 真实健康声明 | 高（正确） |
| **现有虚假声明** | **23-32%**（错误） |
| **虚构虚假声明** | **49-55%**（错误） |

**核心问题**：LLM很少质疑真实健康声明，但**未能挑战虚假声明**。

**预设程度影响**：预设程度增加导致更高同意率，**无论真实性**。

**覆盖预设触发词**：

**嵌入语境分析**：

## 第四节 NLI重排序与RAG验证

### 一、RankRAG：统一排序与生成

Yu等人（NeurIPS 2024, arXiv:2407.02485）的**RankRAG**使用NLI原则进行检索结果排序。

**核心思想**：
- 判断检索文档是否**蕴涵**查询答案
- 过滤矛盾或中立的文档
- 提升回答质量

**实验结果**：

| 基准 | RankRAG | 基线 | 提升 |
|------|---------|------|------|
| 知识密集型QA (9个) | 最优 | ChatQA-1.5 | 超越 |
| 长尾QA | 78.3% | 68.1% | **+10.2%** |
| 多跳QA | 72.5% | 65.3% | **+7.2%** |

### 二、蕴涵感知答案评估

ACL 2024的研究使用蕴涵关系评估QA答案：

**方法**：
1. 将参考答案转换为蕴涵前提
2. 将生成答案转换为假设
3. 使用NLI模型判断关系
4. 蕴涵=正确，矛盾=错误，中立=部分正确

```python
def entailment_based_answer_evaluation(reference, generated):
    """基于蕴涵的答案评估"""
    
    # 构建NLI输入
    premise = f"The answer is: {reference}"
    hypothesis = f"The answer is: {generated}"
    
    # NLI判断
    relation = nli_model.predict(premise, hypothesis)
    
    if relation == "ENTAILMENT":
        return {"correct": True, "score": 1.0}
    elif relation == "CONTRADICTION":
        return {"correct": False, "score": 0.0}
    else:  # NEUTRAL
        return {"correct": "partial", "score": 0.5}
```

## 第五节 思维链蕴涵推理

### 一、SEA-CoT方法

NAACL 2024 Findings的研究比较多种思维链方法：

| 方法 | 特点 |
|------|------|
| CoT | 基础思维链 |
| SC-CoT | 自一致性 |
| **SEA-CoT** | 蕴涵感知选择 |
| QD | 问题分解 |
| Self-Refine | 自我改进 |

**SEA-CoT核心**：使用**蕴涵(E)**和**重叠(O)**目标选择解释。

```python
def sea_cot_reasoning(query, context):
    """蕴涵感知的思维链推理"""
    
    # 生成多个推理路径
    reasoning_paths = generate_multiple_paths(query, context)
    
    for path in reasoning_paths:
        # 计算蕴涵得分
        path.entailment_score = compute_entailment(path, context)
        
        # 计算重叠得分
        path.overlap_score = compute_overlap(path, context)
        
        # 综合得分
        path.score = alpha * path.entailment_score + (1-alpha) * path.overlap_score
    
    # 选择最优路径
    best_path = max(reasoning_paths, key=lambda p: p.score)
    
    return best_path.conclusion
```

## 第六节 预设与蕴涵在RAG中的应用

### 一、预设感知的查询理解

| 查询类型 | 预设 | 处理策略 |
|---------|------|---------|
| "为什么X失败了？" | X失败了 | 先验证X是否失败 |
| "谁又犯了错？" | 之前有人犯错 | 确认先前事件 |
| "在Y之后发生了什么？" | Y发生了 | 确认Y的发生 |

### 二、蕴涵关系用于检索验证

```python
def entailment_based_retrieval_verification(query, retrieved_docs):
    """基于蕴涵的检索结果验证"""
    
    verified_docs = []
    
    for doc in retrieved_docs:
        # 检查文档是否蕴涵查询答案
        relation = check_entailment(doc.content, query)
        
        if relation == "ENTAILMENT":
            doc.verification = "SUPPORTED"
            doc.confidence = "HIGH"
        elif relation == "CONTRADICTION":
            doc.verification = "CONTRADICTED"
            doc.confidence = "HIGH"
        else:
            doc.verification = "UNCERTAIN"
            doc.confidence = "LOW"
        
        verified_docs.append(doc)
    
    # 优先返回支持性文档
    return sorted(verified_docs, 
                  key=lambda d: (d.verification == "SUPPORTED", d.confidence),
                  reverse=True)
```
