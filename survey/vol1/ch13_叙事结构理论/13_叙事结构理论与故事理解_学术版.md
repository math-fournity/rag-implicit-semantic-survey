## 第一节 叙事结构理论基础

### 一、叙事学的核心概念

**叙事（Narrative）**是人类组织和传递经验的基本认知模式。叙事学（Narratology）研究叙事的结构、功能和效果。

**故事（Story）vs 话语（Discourse）**：
- **故事**：事件的时间序列（what happened）
- **话语**：事件的呈现方式（how it is told）

> 同一个故事可以有不同的话语呈现：
> - 顺叙、倒叙、插叙
> - 第一人称、第三人称
> - 详略安排

### 二、经典叙事结构模型

**弗莱塔格金字塔（Freytag's Pyramid）**：

```
        高潮
         /\
        /  \
       /    \
      /      \
     /        \
    /          \
铺垫 — 上升 — 下降 — 结局
```

**英雄之旅（Hero's Journey）**：
Joseph Campbell提出的神话叙事结构：

1. **出发**：日常世界 → 冒险召唤 → 跨越门槛
2. **历险**：试炼 → 深渊 → 转变
3. **回归**：携带恩赐返回日常世界

**七点结构（Save the Cat Beat Sheet）**：
Blake Snyder的电影编剧结构：

| 节点 | 位置 | 功能 |
|------|------|------|
| 开场 | 0-10% | 建立世界和角色 |
| 催化剂 | 12% | 打破平衡 |
| 辩论 | 12-25% | 主角犹豫 |
| 第一幕转折 | 25% | 进入新世界 |
| 中点 | 50% | 虚假胜利/失败 |
| 至暗时刻 | 75% | 最低点 |
| 高潮 | 75-99% | 最终对决 |
| 结局 | 99-100% | 新平衡 |

### 三、叙事连贯性

**叙事连贯性（Narrative Coherence）**是故事可理解性的核心：

- **时间连贯**：事件的时间逻辑
- **因果连贯**：事件间的因果关系
- **角色连贯**：角色行为的一致性
- **主题连贯**：贯穿故事的主题统一

## 第二节 多智能体叙事生成

### 一、Agents' Room框架

Huot等人（Google DeepMind, ICLR 2025, arXiv:2410.02603）的**Agents' Room**是多智能体叙事生成的里程碑工作。

**核心思想**：将故事写作分解为由专业智能体处理的子任务，通过共享记忆板协调。

**智能体架构**：

**规划智能体（Planning Agents）**：
| 智能体 | 职责 |
|--------|------|
| 角色智能体 | 设计角色背景、动机、关系 |
| 冲突智能体 | 构建核心冲突和张力 |
| 场景智能体 | 设计场景和环境 |
| 情节智能体 | 规划事件序列 |

**写作智能体（Writing Agents）**：
| 智能体 | 对应结构 |
|--------|----------|
| 铺垫智能体 | 开场、世界建立 |
| 渐进智能体 | 冲突升级 |
| 高潮智能体 | 转折点 |
| 收尾智能体 | 下降动作 |
| 结局智能体 | 解决和闭合 |

**共享记忆板（Shared Memory Board）**：
- 存储所有智能体的工作成果
- 支持智能体间信息共享
- 维护叙事一致性

**GitHub**：https://github.com/google-deepmind/tell_me_a_story

**效果**：写作智能体生成的故事长度约为端到端方法的**2倍**，人类评估显示质量显著提升。

### 二、CollabStory数据集

Venkatraman等人（NAACL 2025 Findings）构建的**CollabStory**是首个纯LLM协作生成故事数据集。

**规模**：**32,000+故事**

**生成方法**：
- 使用5种开源LLM：Llama2、Olmo、Gemma、Mistral、Orca
- 评估1-5个LLM作者的顺序交接生成

**研究发现**：
- 当前作者检测基线在多LLM协作场景下失效
- 揭示了LLM协作写作的独特模式

**GitHub**：https://github.com/saranya-venkatraman/CollabStory

### 三、Collective Critics框架

Bae & Kim（EMNLP 2024, DOI:10.18653/v1/2024.emnlp-main.1046）提出的**Collective Critics**框架：

**两阶段方法**：
1. **CrPlan**：LLM评论团队优化故事规划
2. **CrText**：LLM评论团队优化故事文本

**评论机制**：多个LLM评论者+领导者通过多轮修订协作。

## 第三节 LLM叙事能力评估

### 一、自动故事评估（ASE）

TACL 2024的研究（Chhun等, arXiv:2405.13769）提出了自动故事评估的**6项标准**：

| 标准 | 定义 |
|------|------|
| **相关性** | 故事与提示的匹配度 |
| **连贯性** | 事件逻辑的一致性 |
| **共情** | 读者与角色的情感连接 |
| **惊喜** | 情节的意外性 |
| **参与度** | 故事的吸引力 |
| **复杂性** | 叙事结构的深度 |

**评估发现**：
- LLM在系统级故事评估上优于传统指标（BLEU、ROUGE）
- 但LLM难以为评分提供令人满意的解释

**数据集**：HANNA（人工标注叙事，1,056故事）

### 二、叙事规划能力评估

arXiv:2506.10161的研究基于文学实例构建基准，测试三种能力：

| 能力 | 定义 | LLM表现 |
|------|------|---------|
| **因果合理性** | 事件因果链的合理性 | 小规模可行 |
| **角色意图性** | 角色行为的动机一致性 | **困难** |
| **戏剧冲突** | 冲突的有效构建 | **困难** |

**关键发现——"逆转诅咒"**：
LLM难以追踪角色关系的双向性。

> 如果A是B的父亲，LLM不一定能推断B是A的孩子。

### 三、CONAN：复杂角色关系提取

Zhao等人（ACL Findings 2024, arXiv:2402.11051）的**CONAN**基准：

- 使用谋杀推理游戏叙事（100个故事）
- 测试LLM处理复杂角色关系的能力

**LLM困难点**：
- 角色别名识别
- 矛盾信息处理
- 隐含关系推理

### 一、SCORE框架

arXiv:2503.23512提出的**SCORE（Story Coherence and Retrieval Enhancement）**框架将RAG与动态状态追踪结合。

**核心方法**：

**语境检索**：
- TF-IDF用于关键词匹配
- FAISS语义嵌入用于语义相似度

**动态状态追踪**：
- 增量知识图谱构建
- 持久故事记忆

**效果**：

| 指标 | SCORE | 基线 | 提升 |
|------|-------|------|------|
| 连贯性（NCI-2.0） | - | - | **+23.6%** |
| 情感一致性 | 89.7% | - | - |
| 幻觉率 | - | - | **-41.8%** |

### 二、NarrativeQA基准

Kočiský等人（TACL 2018）的**NarrativeQA**仍是故事级阅读理解的金标准：

- **规模**：46,765个问答对

- **任务**：需要理解整体叙事才能回答的问题

**当前SOTA方法**：两步检索+生成

2. 神经QA模型生成答案

**排行榜**：https://paperswithcode.com/sota/question-answering-on-narrativeqa

## 第五节 叙事结构在RAG中的应用

### 一、跨检索块的叙事连贯性维护

**问题**：RAG分块破坏叙事连贯性

```
原始叙事：[铺垫] → [冲突] → [高潮] → [结局]
分块后：[块1] [块2] [块3] [块4]
问题：每个块丢失与其他块的叙事关联
```

**解决方案：共享记忆板架构**

```python
class NarrativeRAG:
    def __init__(self):
        self.memory_board = SharedMemoryBoard()
        
    def retrieve_with_coherence(self, query, chunks):
        # 提取叙事元素
        for chunk in chunks:
            chunk.characters = extract_characters(chunk)
            chunk.events = extract_events(chunk)
            chunk.narrative_position = identify_position(chunk)
        
        # 更新共享记忆
        self.memory_board.update(chunks)
        
        # 基于叙事连贯性重排序
        ranked = self.rank_by_narrative_coherence(query, chunks)
        
        return ranked
```

### 二、故事级信息检索

| 查询类型 | 检索策略 | 示例 |
|---------|---------|------|
| 角色查询 | 跨块角色追踪 | "主角最终的结局是什么？" |
| 情节查询 | 因果链检索 | "是什么导致了战争爆发？" |
| 主题查询 | 全文主题分析 | "这个故事的主题是什么？" |

def narrative_aware_generation(query, retrieved_chunks, memory_board):
    """叙事感知的答案生成"""
    
    # 获取叙事上下文
    narrative_context = memory_board.get_context()
    
    # 确定查询的叙事焦点
    focus = identify_narrative_focus(query)
    
    if focus == "CHARACTER":
        # 整合角色相关信息
        context = aggregate_character_info(retrieved_chunks, narrative_context)
    elif focus == "PLOT":
        # 按因果顺序组织
        context = organize_by_causality(retrieved_chunks)
    elif focus == "THEME":
        # 提取主题相关段落
        context = extract_thematic_content(retrieved_chunks)
    
    return generate_answer(query, context)
