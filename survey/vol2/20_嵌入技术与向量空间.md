# 第二卷 RAG技术演进

## 回复20：嵌入技术与向量空间

---

### 概述

**向量嵌入（Embedding）**是RAG系统的基础设施——将文本转换为稠密向量，使语义相似性可以通过向量距离来衡量。从Word2Vec的词级嵌入，到BERT的上下文嵌入，再到E5、BGE等检索专用模型，嵌入技术的演进深刻影响着RAG系统的能力边界。

本回复将系统梳理嵌入技术的发展历程，分析不同模型的特点，并为RAG场景下的嵌入模型选型提供指导。

---

### 一、嵌入技术演进

#### 1.1 静态词嵌入时代（2013-2018）

**Word2Vec（2013）**

Mikolov等人提出的开创性工作：

**CBOW（连续词袋）**：
通过上下文预测中心词。

**Skip-gram**：
通过中心词预测上下文。

核心思想：**分布式假说**——相似语境中出现的词有相似含义。

$$\max \sum_{t=1}^{T} \sum_{-c \le j \le c, j \neq 0} \log P(w_{t+j}|w_t)$$

**GloVe（2014）**

Global Vectors for Word Representation：
- 结合全局统计与局部上下文
- 基于词共现矩阵分解

$$J = \sum_{i,j=1}^{V} f(X_{ij})(w_i^T \tilde{w}_j + b_i + \tilde{b}_j - \log X_{ij})^2$$

**FastText（2016）**

考虑子词（subword）信息：
- 处理未登录词（OOV）
- 捕获形态学信息
- 对拼写变体更鲁棒

**静态嵌入的局限**：

```
"bank"在两个句子中：
1. "I deposited money in the bank."
2. "I sat by the river bank."

静态嵌入：两个"bank"有相同向量 ✗
```

一词一向量，无法处理多义词。

#### 1.2 上下文嵌入时代（2018-2022）

**ELMo（2018）**

Embeddings from Language Models：
- BiLSTM语言模型
- 词的表示依赖上下文
- 多层表示的加权组合

**BERT（2018）**

Bidirectional Encoder Representations from Transformers：
- Transformer编码器
- 双向上下文建模
- 预训练+微调范式

$$\text{MLM}: P(x_{\text{masked}}|\text{context})$$
$$\text{NSP}: P(\text{IsNext}|A, B)$$

**上下文嵌入的优势**：

```
"bank"的上下文表示：
1. "I deposited money in the bank." → 银行相关向量
2. "I sat by the river bank." → 河岸相关向量

同一个词，不同上下文，不同向量 ✓
```

**BERT用于文本检索的方式**：

**[CLS] Token**：
使用[CLS]位置的输出作为整个文本的表示。

**Mean Pooling**：
对所有token的输出取平均。

**Max Pooling**：
对所有token的输出取最大值。

#### 1.3 检索专用嵌入时代（2022-）

通用BERT并非为检索优化，存在问题：
- [CLS]表示不够区分性
- 未针对相似度计算优化
- 训练目标与检索不匹配

**对比学习优化**：

$$\mathcal{L} = -\log \frac{\exp(sim(q, d^+)/\tau)}{\sum_{d \in \{d^+, d^-\}} \exp(sim(q, d)/\tau)}$$

将相关对拉近，不相关对推远。

**代表性检索嵌入模型**：

| 模型 | 机构 | 特点 |
|-----|------|-----|
| E5 | Microsoft | Embeddings from Bidirectional Encoder |
| BGE | BAAI | Beijing Academy of AI |
| GTE | Alibaba | General Text Embeddings |
| Jina | Jina AI | 多语言、长文本 |
| Cohere Embed | Cohere | 商业API |
| OpenAI text-embedding | OpenAI | 商业API |

### 二、主流嵌入模型详解

- 1536维

- 通用性好

**text-embedding-3-small/large（新版）**：

- small: 1536维, large: 3072维

**特点**：

- 持续更新优化
- 多语言支持好

**考量**：
- API调用成本
- 数据隐私（数据发送到外部）
- 网络依赖

#### 2.2 E5系列

Microsoft的开源嵌入模型：

**E5-base/large/small**：
- 基于BERT架构
- 对比学习训练
- 指令感知变体（E5-instruct）

**E5-Mistral-7B-Instruct**：
- 基于Mistral-7B
- LLM级别的嵌入能力
- 支持长文本

**使用方式**：

```

query = "query: How to use RAG?"
passage = "passage: RAG combines retrieval with generation..."
```

#### 2.3 BGE系列

BAAI（北京智源研究院）开发：

**BGE-base/large/small**：
- 中英文支持好

**BGE-M3**：
- 支持100+语言
- 统一稠密、稀疏、多向量检索
- 长达8192 token

**BGE-Reranker**：
- 交叉编码器重排序模型
- 与BGE嵌入配合使用

#### 2.4 GTE系列

阿里巴巴开发：

**GTE-base/large/small**：
- 多阶段对比学习
- 中英文优化

**GTE-Qwen系列**：
- 基于Qwen架构
- 更长上下文支持
- 指令跟随能力

#### 2.5 商业vs开源比较

| 维度 | 商业API | 开源模型 |
|-----|---------|---------|
| 部署难度 | 简单（API调用） | 需要GPU部署 |

### 三、向量空间与相似度计算

#### 3.1 相似度度量

**余弦相似度（Cosine Similarity）**：

$$\text{cos}(u, v) = \frac{u \cdot v}{\|u\| \|v\|}$$

- 范围：[-1, 1]
- 仅考虑方向，不考虑模长
- 最常用

**点积（Dot Product）**：

$$\text{dot}(u, v) = u \cdot v$$

- 范围：无界
- 同时考虑方向和模长
- 当向量归一化后，等价于余弦相似度

**欧氏距离（Euclidean Distance）**：

$$\text{L2}(u, v) = \|u - v\|_2$$

- 范围：[0, +∞)
- 需要转换为相似度（通常取负或倒数）
- 受向量模长影响

**选择建议**：

| 场景 | 推荐度量 |
|-----|---------|
| 归一化向量 | 余弦相似度或点积（等价） |
| 非归一化向量 | 余弦相似度 |
| 需要考虑模长 | 点积 |
| 聚类任务 | 欧氏距离 |

#### 3.2 向量空间的几何特性

**维度的作用**：

- 更高维度→更多表达能力
- 但也带来存储和计算成本
- 存在性能-效率权衡

**常见维度**：
- 384维（小模型）
- 768维（base模型）
- 1024维（大模型）
- 1536维（OpenAI ada）
- 3072维（OpenAI large）

**维度压缩技术**：

**PCA（主成分分析）**：
保留主要方差方向。

**Matryoshka表示**：
训练时使嵌入的前k维本身就是有效的k维嵌入。

$$\mathcal{L} = \sum_{k \in \{32, 64, 128, ...\}} \mathcal{L}_k$$

OpenAI text-embedding-3支持此特性。

#### 3.3 语义空间的结构

**语义聚类**：

相似概念在向量空间中聚集：
- "猫"、"狗"、"兔子"在"宠物"区域
- "汽车"、"飞机"、"火车"在"交通工具"区域

**类比关系**：

著名的"king - man + woman ≈ queen"：

$$\vec{king} - \vec{man} + \vec{woman} \approx \vec{queen}$$

但在实际应用中，这种关系不总是稳定。

**各向异性问题**：

BERT等模型的嵌入空间存在各向异性：
- 向量分布不均匀
- 集中在某个方向的狭窄锥形区域
- 影响相似度计算的区分度

**解决方法**：
- 后处理白化（Whitening）
- 训练时优化
- 对比学习自然缓解

### 四、RAG场景下的嵌入考量

#### 4.1 查询与文档的不对称性

**长度不对称**：
- 查询：通常较短（几个词到一两句）
- 文档：通常较长（段落到多段）

**信息密度不对称**：
- 查询：信息密集，每词重要
- 文档：信息分散，有冗余

**处理策略**：

**双编码器（Bi-encoder）**：
查询和文档使用相同/不同编码器独立编码。

**非对称训练**：
针对查询-文档对的特点训练。

**指令前缀**：
```
Query: "query: What is RAG?"
Document: "passage: RAG is a technique that..."
```

#### 4.2 长文本处理

**上下文窗口限制**：

| 模型 | 最大长度 |
|-----|---------|
| BERT | 512 tokens |
| E5-base | 512 tokens |
| BGE-M3 | 8192 tokens |
| GTE-Qwen | 8192+ tokens |
| Jina-v2 | 8192 tokens |

**超长文本策略**：

**截断**：
简单但丢失信息。

**分块嵌入**：
将长文档分块，各块独立嵌入。

**层次嵌入**：
先分块，再对块的嵌入进行聚合。

**长文本模型**：
使用专门支持长文本的模型。

#### 4.3 多语言考量

**单语言模型**：
- 对特定语言优化
- 通常效果更好

**多语言模型**：
- 一个模型支持多种语言
- 跨语言检索能力
- BGE-M3、E5-multilingual

**跨语言检索**：

```
Query (中文): "什么是RAG技术？"
Document (英文): "RAG combines retrieval with generation..."

多语言模型可以匹配
```

#### 4.4 领域适应

**通用vs领域专用**：

| 类型 | 优点 | 缺点 |
|-----|------|-----|
| 通用模型 | 覆盖广、无需额外训练 | 领域术语理解不深 |
| 领域专用 | 领域理解深入 | 覆盖窄、需要训练 |

**领域适应方法**：

**继续预训练**：
在领域语料上继续预训练。

**对比学习微调**：
用领域相关对进行对比学习。

**提示工程**：
对支持指令的模型，在指令中描述领域。

**领域专用模型示例**：
- BioBERT（生物医学）
- LegalBERT（法律）
- FinBERT（金融）
- SciBERT（科学）

### 五、嵌入模型评估

#### 5.1 评估基准

**MTEB（Massive Text Embedding Benchmark）**：

最全面的嵌入评估基准：
- 8大任务类别
- 58个数据集
- 112种语言

任务类别：
1. Bitext Mining（双语挖掘）
2. Classification（分类）
3. Clustering（聚类）
4. Pair Classification（对分类）
5. Reranking（重排序）
6. Retrieval（检索）
7. STS（语义文本相似度）
8. Summarization（摘要）

**BEIR（Benchmark for Information Retrieval）**：

零样本检索评估：
- 多领域覆盖
- 测试泛化能力

#### 5.2 评估指标

**检索相关**：
- nDCG@10：归一化折损累积增益
- Recall@k：召回率
- MRR：平均倒数排名

**语义相似度**：
- Spearman相关系数
- Pearson相关系数

#### 5.3 选型决策框架

```
开始
  │
  ├─ 是否可以使用外部API？
  │     │
  │     ├─ 是 → 考虑 OpenAI/Cohere
  │     │       （简单、效果好、有成本）
  │     │
  │     └─ 否 → 继续下一步
  │
  ├─ 是否需要多语言？
  │     │
  │     ├─ 是 → BGE-M3 / E5-multilingual
  │     │
  │     └─ 否 → 继续下一步
  │
  ├─ 是否需要长文本（>512 tokens）？
  │     │
  │     ├─ 是 → BGE-M3 / GTE-Qwen / Jina-v2
  │     │
  │     └─ 否 → E5 / BGE / GTE
  │
  ├─ 是否有特定领域？
  │     │
  │     ├─ 是 → 考虑领域微调或专用模型
  │     │
  │     └─ 否 → 通用模型即可
  │
  └─ 计算资源约束？
        │
        ├─ 有限 → small变体
        │
        └─ 充足 → large变体
```

### 六、前沿趋势

#### 6.1 LLM-based嵌入

使用LLM生成嵌入：
- E5-Mistral-7B-Instruct
- GTE-Qwen
- Nomic-embed

优势：
- 更强的语义理解
- 指令跟随能力
- 更好的泛化

挑战：
- 计算成本高
- 推理速度慢

#### 6.2 稀疏-稠密混合

结合稀疏表示和稠密表示：
- BGE-M3支持统一表示
- 稀疏：精确匹配
- 稠密：语义匹配

#### 6.3 多向量表示

每个文档用多个向量表示：
- ColBERT风格
- 保留更多细粒度信息
- 匹配更灵活
